# OpenCode 工作台（agent workbench）

## 目标

在不离开一个窗口的前提下，用户能同时做三件事：浏览/编辑项目代码、跟 OpenCode 的 agent 对话（看它改了什么、随时插话）、执行终端命令。
面向的典型场景：让 agent 改一个模块，自己盯着 diff、顺手改两行、再让它继续。

## 不做什么

- 不做 LSP（跳转定义、诊断、类型级补全）；日常补全用本地词法 + 同目录符号实现，够用且零依赖
- 不做调试器 / DAP
- 不做插件市场、主题商店
- 不做多人协作、云端同步
- 不改 OpenCode 本体和它的后端，只当客户端用
- 第一版不做移动端适配

## 验收标准

1. 启动后 ≤ 3 秒出现三栏界面：左文件树、中编辑器、右会话面板。
2. 左栏展开 `F:\opencode\workbench`，能看到真实目录；点一个 `.ts` 文件，中间显示带行号的源码。
3. 在中间改一行并保存（Ctrl+S），磁盘文件内容随之改变（用 `Get-Content` 验证）。
4. 右栏新建会话并发送"列出当前目录的文件"，能看到流式回复和工具调用记录。
5. 底部终端能执行 `echo hello` 并显示输出。
6. agent 改完文件后，diff 面板能列出变更文件，并显示增删行。
7. 关闭并重开程序，上次打开的文件和会话仍在。
8. 后端服务不可用时，界面顶部显示"未连接"，不白屏、不崩。
9. 打开 30 MB / 60 万行日志：能滚到第 60 万行，DOM 行数 < 200；连续快速点击多个大文件不卡死。
10. 1 MB 以上 Markdown 默认停在源码分页模式；HEIC/PNG 之外的二进制显示前 4 KB 十六进制。

## 前置条件

- 数据来源：本机 `opencode serve` 的 HTTP API（实测 v2.2.5，端口由 `opencode service status` 给出）。核心端点：
  - 文件：`/api/fs/list`、`/api/fs/read/<path>`、`/api/experimental/fs/write`、`/api/experimental/fs/watch`
  - 会话：`/api/session`、`/api/session/<id>/prompt`、`/api/session/<id>/message`、`/api/session/<id>/diff`
  - 事件：`/api/event`（SSE）
  - 终端：`/api/pty`
  - Git：`/api/vcs/status`、`/api/vcs/diff`
- 鉴权：走 `opencode pair` 的一次性链接换取会话凭据；没有凭据时显示配对页。
- 没有项目时：显示"打开文件夹"，允许输入路径。

## 非功能要求

- 性能：启动到可操作 ≤ 3 秒；打开 1 MB 文本文件 ≤ 500 ms；文件树展开 1000 条目目录 ≤ 300 ms；打开任意大小文件的首屏只与视口行数相关（不随文件大小线性变慢），滚动时 DOM 行数保持 ≈ 视口 + 120 行。
- 兼容：Windows 10/11；opencode v2.2.x 的 API。
- 安全：不把 API 凭据写进日志；不上传任何文件内容到第三方；默认只绑定 127.0.0.1。

## 约束

- 不能改 opencode 本体、不能要求它打补丁。
- 不能依赖它内置 web 前端的具体产物（版本一变路径就废），只依赖 HTTP API。
- 单文件代码 ≤350 行（fsapi/fsread/CodeView 这类视图或协议聚合文件按现状；新增模块尽量 ≤300 行），单函数不超过 50 行。

## 假设（待确认）

- 假设第一版以"浏览器打开本地页面"的形式验证手感，跑通后再套桌面壳（Tauri 或 WebView2）。
- 假设用户接受「不做 LSP」：补全靠当前文件符号 + 同目录符号 + 关键字 + import 路径；要跨文件类型推导再评估 LSP。
- 假设终端用 opencode 自带的 PTY 接口，不自建 pty 进程。
