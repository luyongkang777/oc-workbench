# 远程访问 / 多实例 web 托管

## 目标

在外面（手机、别的电脑）用一个公网地址打开任意一台跑着 oc-workbench 的电脑，看到它的对话和任务并继续操作。

要能给别人用：同一个入口地址，多个人 / 多台机器各走各的，互不串号。

## 隔离模型（先看这个，它决定了后面所有设计）

**隔离单位是「实例（进程）」，不是「人」。**

一个实例 = 一台机器上的一个 exe 进程，共用一套登录状态。所以：

- 两个人拿到同一个链接 → 进的是同一个界面，互相能覆盖操作。
- 想各自独立 → 一台机器两个实例（现在被单实例锁挡住，见「不做什么」）。
- 正确用法：**一人一个实例、一人一个链接。**

隔离靠三层，缺一不可：

| 层 | 挡什么 | 实现 |
| --- | --- | --- |
| 路由层 | 走错机器 | 网关按前缀把 `/u/A/` 只转到 17801、`/u/B/` 只转到 17802，映射是死的 |
| 凭据层 | 拿别人凭据进 | **每台机器用自己的 `remoteToken` 签名 cookie**，网关不持有任何凭据 |
| 注册层 | 冒充别人机器 | 每个实例独立 secret，网关只存哈希 |

### 为什么不可能串号

网关是哑管道，不存任何人的 token；cookie 由各实例自己的 `remoteToken` 签名。推演：

| 场景 | 结果 | 原因 |
| --- | --- | --- |
| A 把 URL 的 `/u/A/` 改成 `/u/B/` | 401 | B 用自己的 key 验签，A 的 cookie 过不了 |
| C 复制 A 的 cookie 塞进自己浏览器 | 401 | 同上，签名 key 不同 |
| C 暴力扫路径 | 扫到也进不去 | 路径不是凭据，还要过签名校验 |

**反例（不要这么做）**：网关做「统一登录 + 下拉框选机器」。那网关必须持有所有人的凭据，串号就成必然。配置里要写注释禁止。

## 代码现状与改造点

| # | 现状 | 解法 |
| --- | --- | --- |
| 1 | `server.rs:338` 绑 `127.0.0.1:0`，端口随机 | 端口从 `settings.json` 读，默认仍是 0（不设等于现状） |
| 2 | `server.rs:455` Host 必须精确 `127.0.0.1:<本地端口>` | **不改代码**：nginx 里写死 `proxy_set_header Host 127.0.0.1:17800;` |
| 3 | `server.rs:472` token 每次启动随机、只走 IPC | 新增持久化 `remoteToken` + HMAC cookie |
| 4 | `server.rs` 路由写死 `/api/*`、`/` | 加可配前缀，剥掉再匹配 |
| 5 | `main.rs:163` 加载 `http://127.0.0.1:{port}/` | 加前缀后必须拼上 base，否则 404 白屏 |

关于第 2 条，重点说明：nginx 的 `$host` **不带端口**，后端 `rsplit_once(':')` 会失败；而且校验时端口必须等于**本地端口 17800**，写成 `7800` 也过不了。所以正确做法是 nginx 直接改写成一个合法回环 Host，后端一行不用改，也不用开白名单（白名单本身是安全弱点）。

## 凭据设计

`settings.json` 新增三个键（沿用现有读写函数，不加新依赖）：

| 键 | 说明 |
| --- | --- |
| `remoteToken` | 32 字节随机 hex，**持久不变**，首次启动生成 |
| `remotePort` | 本地监听端口，默认 0（随机） |
| `remoteBase` | 路径前缀，如 `/u/7fk2m9xq`，默认空 |

cookie 格式：

```
oc_sess = <exp>.<hex(HMAC-SHA256(remoteToken, instanceId + "|" + exp))>
HttpOnly; Path=<base>/; SameSite=Lax; Max-Age=2592000
```

- 自包含签名，**不存 session 表**，重启后 cookie 仍有效
- 每台机器 `remoteToken` 不同 → 天然做到「凭据与实例绑定」
- `sha2` 和 `getrandom` 已经在 `Cargo.toml` 里，不新增编译单元

## 架构

```
手机/外面
  → http://81.70.181.82:7800/u/<实例ID>/?t=<remoteToken>
  → nginx :7800 按前缀分流（Host 改写成本地回环）
  → 127.0.0.1:1780X（每实例一个回环端口）
  ← ssh -R（本机主动出站）
  → 该机 workbench :17800
  → opencode 服务
```

公网只开 7800。多一台机器只在服务器多一个**回环**端口，不占公网端口。

## 一期范围

单实例跑通，但配置键、路径前缀、cookie 设计全部按多实例来，二期接第二台不用返工。

## 前置条件（「给别人用」之前必须满足）

这些不在代码里，但不满足就白做：

1. **对方机器上 opencode 能跑。** workbench 只是壳，所有能力来自本机 opencode 服务。没装、没登录、没额度 → 打开就是「未连接」。
2. **对方机器是 Windows 且能跑这个 exe**（WebView2 依赖）。
3. **带宽够。** 2C4G 轻量通常 4~6 Mbps（需去控制台确认）。纯文本够用，多人同看大日志/图片会卡。这决定「最多给几个人用」。
4. **对方能接受流量过你的服务器**，费用和带宽是你的。

## 不做什么（一期）

- 不做子域名 / HTTPS（没域名，工作量翻倍）。
- 不做自动分配实例 ID（一期手工配）。
- 不做跨机会话汇总（数据在各自本地）。
- 不做同机多实例（`single.rs` 是全局互斥体 `Local\oc-workbench-single-instance`，要支持得加 profile 后缀）。
- 不动现有生产站点，不在 80 上加 location。
- 不改 `host_allowed()`，不改 `x-oc-token` 原有行为（WebView2 外壳照旧能用）。

## 验收标准

**链路**

1. 手机 4G（不连家里 WiFi）打开 `http://81.70.181.82:7800/u/<id>/?t=<token>`，能进主界面。
2. 刷新页面不用再带 token（cookie 生效）。
3. 重启 exe 后，之前发出去的链接**仍然有效**（`remoteToken` 持久化）。
4. 无 cookie 直接访问 `<base>/` 被拒；访问 `/` 和 `/u/其它ID/` 拿不到本实例。

**功能**

5. 发一条消息，流式回复正常（SSE 不被缓冲）。
6. 文件面板（`/local/fs/*`）、Git 面板（`/local/git/*`）在前缀下正常。
7. 手机锁屏 1 分钟、切到微信再回来，发消息仍有反应（SSE 自愈）。

**安全**

8. 用 A 的 cookie 请求 B 的路径 → 401。
9. 不带任何凭据的 `/api/*` → 401/403。

**不破坏现有**

10. `http://81.70.181.82/` 200、`:3900` 正常、`:7810` `:7820` healthz 仍通。
11. `npm run build`、`cargo build --release`、`npm test` 全绿。

**运维**

12. 手工断开隧道，60 秒内自动恢复。
13. 从**本机**（非服务器）连 7800 能通（验证轻量防火墙已放行）。

## 排错与回滚

**三层排错，按顺序看：**

| 现象 | 查哪里 |
| --- | --- |
| 公网连不上（TimedOut） | 轻量控制台防火墙没放行 7800 |
| 公网 502/504 | 隧道断了：服务器 `ss -lntp \| grep 1780X` |
| 502 但在监听 | 本机 exe 没起，或端口不是 1780X |
| 页面白屏 | `main.rs` 加载 URL 没拼 base |
| 403 | Host 头不对，检查 nginx 的 `proxy_set_header Host` |
| 401 | cookie 过期或 token 不对 |
| 能进但「未连接」 | 本机 opencode 服务没跑起来 |

**日志位置**：本机 `log_path()`（`main.rs:800`）、服务器 nginx error.log、隧道 stdout。

**回滚**：一期全部是新增。删掉服务器那个 nginx conf + reload，就恢复原状；本机不设 `remotePort`/`remoteBase` 就是原来的行为。

## 风险

| 风险 | 说明 | 应对 |
| --- | --- | --- |
| SPA 绝对路径 | 第二台接上来资源 404 | 一期就把 base 做进去并验证 |
| 明文 HTTP | URL 里的 token 可被中间人看到 | 长随机路径 + 一次性换 cookie + `Referrer-Policy: no-referrer`；二期上 HTTPS |
| 能力等于扣子 | 能连上就能执行命令、读文件 | cookie 与实例绑定，网关不落 token 日志 |
| ssh -R 不适合给别人 | 不能给每个用户发服务器账号 | 一期只给自己机器；二期换自研连接器 |
| 单实例锁 | 同机不能跑两个实例 | 二期加 profile 后缀 |
